# Сделай презентацию

Отвечай за готовый результат и самостоятельные решения. Восстанови задачу, актуальные исходники, ручные правки и принятые решения. Аудитория, предмет, желаемое действие, способ просмотра и формат определяют работу. Уточняй только существенное неизвестное; не превращай работу в согласование каждого этапа.

## Выбери маршрут

| Запрос | Какие навыки нужны |
|---|---|
| Новая презентация | [Структура](../presentation-structure/SKILL.md) → [контент](../presentation-content/SKILL.md) → [наглядное объяснение](../presentation-visualize/SKILL.md) для сложного материала → [дизайн](../presentation-design/SKILL.md) → [сборка](../presentation-build/SKILL.md) |
| Новое оформление готового материала | [Редизайн](../presentation-redesign/SKILL.md) определяет сохраняемое и ведёт к дизайну и сборке |
| Небольшие исправления | [Доводка](../presentation-polish/SKILL.md) |
| Собрать удачные слайды или сохранить отмеченные | [Отбор в личную библиотеку](references/collect-slides.md) по готовым страницам |
| Только оценка | [Критика](../presentation-critique/SKILL.md), без изменения файлов |
| Только часть работы | Нужный навык заканчивает своим результатом; весь маршрут не запускается |

Загружай инструкцию активного навыка и нужные ему справочники. Готовый результат позволяет пропустить этап после проверки применимости. Утверждённый текст не нужно заново писать, заданный стиль — заново выбирать. Передавай результат через [рабочий план](references/handoff.md), без отдельных реестров и всей истории обсуждения.

До выбора оформления проверь, найдена ли действующая дизайн-система проекта, даже если пользователь её не упомянул. Применяй её по [правилам дизайн-контекста](references/design-context.md); найденное при исследовании передавай в дизайн вместе с содержанием. Авторский режим не даёт основания заново выбирать утверждённые цвета и типографику.

## Два режима

По умолчанию — **авторский**. **Быстрый** применяется по прямому запросу. Сообщи выбор в начале без дополнительного согласования.

| | Быстрый | Авторский |
|---|---|---|
| Свободный стиль | Одно обоснованное направление | Три разные концепции на одинаковом реальном содержании |
| Проверка воплощения | Один сложный опорный слайд | Два–три опорных слайда разных содержательных типов |
| Независимая критика | По конкретной необходимости | Контент до дизайна; дизайн опорных слайдов до полной сборки |
| Исправления | Общий список и проверка исправленного | Один собранный круг на этапе; повтор по оставшимся существенным проблемам |

В маленькой задаче сократи опорный набор до реально разных типов материала. При заданном стиле конкурс стилей не нужен. Быстрый режим сокращает варианты и обслуживание, сохраняя достоверность, ясность и исправность файла.

## Что удерживать между этапами

- Источники определяют содержание до сборки. Поздний источник, меняющий вывод, возвращает затронутую часть автору контента.
- Сохраняй полезные отношения: общую шкалу, участников и действия, временную линию, причину и следствие. Аккуратный текст не компенсирует потерю объяснения.
- Выбранный прототип развивается в реальный опорный слайд. Замысел должен пережить экспорт.
- Замечание закрывается наблюдаемым исправлением. Повторяющуюся ошибку исправляй во всей затронутой области; частное пожелание не превращай в универсальное правило.
- Содержание и дизайн оцениваются раздельно. Улучшение одного не оправдывает ухудшение другого.

Формат и место результата определяет запрос. Для обычного запроса на файлы используй PPTX и PDF. Технический навык подключается при сборке; его удобство не должно заранее сужать художественный поиск. Генерация изображений и графика кодом доступны без искусственных квот; сохраняй исходники.

Показывай существенные решения и реальные изображения. Жди согласования по явному требованию пользователя либо при недостающем существенном решении. В конце отдай проверенные файлы и предметно назови ограничения.
