# Общий план и передача результатов

У каждого навыка свой результат. Для полной презентации используй один существующий план с устойчивыми `id` слайдов и существующий `design.md`. Для отдельного небольшого задания достаточно принятого формата проекта; ради опечатки новый JSON не нужен.

В плане сохраняются: задача и аудитория; источники и точные места; слайды с ролью, вопросом, тезисом, содержанием и данными; существенные отношения; принятые решения и нерешённые вопросы. Произвольные дополнительные поля старых планов сохраняются. Не переписывай все старые проекты ради нового формата.

Минимальный пример структуры (это формат, не шаблон содержания):

```json
{
  "goal": "Что должен понять или сделать читатель",
  "audience": "Кому объясняем",
  "viewing": "Самостоятельное чтение",
  "sources": {"source-1": {"path": "Материалы.pdf", "locator": "страница 4"}},
  "design": "design.md",
  "slides": [{
    "id": "s01", "role": "объяснение", "question": "Вопрос читателя",
    "thesis": "Ответ слайда", "title": "Заголовок", "text": "Готовый текст",
    "source_ids": ["source-1"],
    "explanation": {"form": "timeline", "must_preserve": ["Событие внутри процесса"]}
  }]
}
```

## Компактное состояние этапов

Для работы с несколькими этапами есть `scripts/presentation_pipeline.py`. Оно дополняет существующий `context`, не создаёт второй план и не требует отдельных файлов отзывов. Старые `presentation_context.py` и `presentation_workflow.py` сохранены для совместимости; новый маршрут не требует старых пропусков `check --before`.

```sh
python3 scripts/presentation_pipeline.py status "/проект/План слайдов.json"
python3 scripts/presentation_pipeline.py handoff "/проект/План слайдов.json" content --slides s01 s02
python3 scripts/presentation_pipeline.py complete "/проект/План слайдов.json" content --slides s01 s02 --summary "Проверены объяснения и основания" --review self
```

`handoff` читает план и отдаёт относящиеся к этапу сведения. `complete` сохраняет результат по слайдам и контрольные суммы явно переданных файлов `--files`; `status` показывает изменившееся. Программа проверяет актуальность, но не достоверность и художественное качество. `--review independent` допустим лишь после действительного отдельного просмотра; его содержание кратко записывается в `--summary`. По умолчанию это `self`, а не автоматическая приёмка.

Этапы: `structure`, `content`, `visualize`, `design`, `build`. Изменение одного числа не обнуляет состояние соседних слайдов и выбранный стиль. Если число хранится в `data`, на затронутом слайде проверяются также наглядное объяснение и дизайн: могла измениться длина полосы, шкала или перенос. Изменение текста делает устаревшими содержание и сборку соответствующего слайда; критик/исполнитель отдельно решает, затронуты ли отношения и композиция. Изменение смысловых полей (`thesis`, `explanation`, `visual`) меняет соответствующие результаты. Смена дизайн-документа или формата слайда затрагивает дизайн и сборку. Новое или пересмотренное решение по одному слайду возвращает на эти этапы только его. Файлы, указанные внутри проекта относительными путями, можно переносить вместе с планом.

Файлы результата регистрируются одной командой после реальной работы. Не добавляй PPTX целого комплекта в зависимости каждого раннего этапа: для дизайна достаточно нужных изображений и исходника, для выпуска — конечных файлов. При частичном изменении сохраняются остальные записи того же этапа.

## Возвращение к предыдущему этапу

- Новый факт или иной вывод — контент и затронутое объяснение.
- Новые участники/связи/переменные — наглядное объяснение и затронутый дизайн.
- Опечатка, короткая подпись, обновление значения с сохранением смысла — локальная доводка и проверка зависимостей.
- Новая художественная концепция — дизайн; сохранённое содержание повторно не исследуется.

Значимые ручные правки сначала переносятся в источник сборки. Проверяющему передаются фактические материалы и ограничения, без заверений автора об успехе. Независимые авторы не должны одновременно записывать один план; объединение результата выполняет ведущий исполнитель.
