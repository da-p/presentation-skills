# От образца к редактируемому слайду

Подключай после выбора композиции. Содержание, масштаб просмотра и формат образца должны соответствовать опорному слайду. Сравнение разных сюжетов помогает выбрать характер, но не подтверждает точность переноса.

## Что измерить и подготовить

Открой образец и самостоятельно перечисли видимые главные элементы: главный объект, набор, изображение, отношения, фактура, свободные области. Затем сопоставь с `design.md` и `visual.retain`. Не ограничивай наблюдение уже записанными автором свойствами.

Для сложного опорного слайда сохрани рядом с его исходниками небольшую спецификацию композиции: размеры холста, области ключевых элементов, выбранные изображения и реальные шрифты. Это исходник сборки; не создавай его для каждого обычного слайда. Если такие данные уже есть в программе сборки, используй их, не веди вторую спецификацию.

Области задаются долями холста `[x, y, width, height]`, от 0 до 1. В `note` укажи видимое свойство, например «название встроено в изображение; правый край буквы перекрыт предметом». Значения измеряются по образцу, не выводятся из названия стиля. Содержимое `regions` можно хранить в `visual.composition` существующего плана; для команды достаточно временно передать этот объект как JSON.

```json
{"regions":[
  {"id":"главный-объект","kind":"image","box":[0.05,0.18,0.60,0.70],"note":"Объект занимает основную площадь"},
  {"id":"объяснение","kind":"text","box":[0.70,0.22,0.25,0.55],"note":"Подписи связаны с частями объекта"}
]}
```

Это пример формата, не готовая раскладка. Отношения, перекрытия и пропорции выбираются по принятой композиции.

## Инструменты

Используй Python из `load_workspace_dependencies`: `slide_craft.py` использует уже входящий в комплект Pillow. Не устанавливай пакет глобально. При недоступности инструментов можно измерить области вручную и показать пары изображений доступным средством; отсутствие автоматизации не разрешает подменить образец привычной сеткой.

```sh
python3 scripts/slide_craft.py grid "/проект/Образец.png" --out "/проект/.tmp/Сетка.html"
python3 scripts/slide_craft.py layout "/проект/Композиция.json" --width 1280 --height 720
python3 scripts/slide_craft.py measure-type "/путь/Шрифт.ttf" --text "Реальный заголовок" --size 48
python3 scripts/slide_craft.py compare "/проект/Образец.png" "/проект/Слайд.png" --spec "/проект/Композиция.json" --out "/проект/.tmp/Сравнение.html"
```

`grid` показывает сетку 10%; `layout` переводит области в координаты выбранного холста, пригодные для параметров сборки. `measure-type` измеряет фактический набор выбранным файлом шрифта, без автоматического уменьшения. Это предварительная проверка; итоговые переносы проверяются в целевом редакторе. `compare` создаёт автономную страницу с двумя изображениями и парами одинаковых областей. Просмотри её или сами изображения; сохранение HTML не означает проверки. Инструменты не выставляют оценку дизайна и не переписывают входные файлы.

## Как собирать

Сначала подготовь ключевую графику и шрифты, затем воспроизведи основной объект и отношение к набору. Текст, таблицы и точные данные оставляй редактируемыми; сложная иллюстрация может быть изображением. Проверь необходимую прозрачность, кадрирование и видимые края. Не пытайся заменить выразительную иллюстрацию случайным набором простых фигур. Не превращай весь слайд в растр ради сходства.

Используй координаты и размеры из спецификации в параметрах генератора; не пересчитывай их независимо в нескольких местах. Сравни первый рендер с образцом в одном масштабе. Проверь главный объект, характер букв, видимую плотность, фактуру и связи. Если содержание изменилось, отдельно проверь смысл; сходство изображений не подтверждает точность объяснения.

Собери существенные отклонения в один список и исправь их пакетом. После одного подтверждающего просмотра повторяй работу только из-за конкретного оставшегося дефекта, непринятого замысла или нового требования. При повторении той же проблемы меняй способ реализации, а не запускай бесконечную подгонку. Для точных микроправок используй [типографику](typography.md), для вариантов объяснения — [разобранные примеры](worked-examples.md).
