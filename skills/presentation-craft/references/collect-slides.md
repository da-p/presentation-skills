# Как собирать удачные слайды

Используй этот метод, когда пользователь просит собрать библиотеку из презентации, сохранить конкретный слайд или пополнять подборку после выпусков. Пожелание «собирай удачные слайды этого проекта» запиши один раз в действующие инструкции проекта вместе с выбранной папкой. Тогда отбор выполняется после выпуска по уже просмотренным финальным слайдам. Отметку «в библиотеку» можно обработать сразу.

## Что брать

1. Посмотри фактический слайд целиком. Для PPTX и PDF используй готовый проверенный рендер или экспорт нужной страницы. Для подборки из нескольких презентаций сначала просмотри миниатюры, затем открой кандидатов в полном размере. Когда пользователь указал номера, начни с них. Для отдельного изображения достаточно имени источника.
2. Назови задачу читателя и видимый приём, который её решает. Это может быть общая шкала, развилка с обратной связью, кадрирование вокруг заголовка или контраст двух шрифтов, различающий голоса. Проверь, понятны ли связи и подписи в конечном размере. Для художественного примера укажи, какую роль играют изображение, набор или свободное место.
3. Запиши, в какой **другой** задаче приём пригодится. Из близких вариантов возьми тот, где он виден яснее. Учти слайды, которые особо отметил пользователь. Если сохранять нечего, заверши отбор без записи. Количество карточек определяет материал.
4. Используй личную коллекцию для собственных работ и материалов, которые пользователь отобрал для повторного использования. Если слайды с закрытыми данными должны оставаться в проекте, укажи отдельную папку проекта. Для общей коллекции можно использовать согласованную обезличенную версию.

## Как сохранить

Пользователю достаточно назвать презентацию или номера. Исполнитель сам готовит временный JSON со списком просмотренных страниц. Пути к картинкам разрешаются относительно этого файла. Пиши в `source` узнаваемое название или имя исходника, в `slide` — номер с единицы. Для отдельной картинки номер можно опустить. У референса из открытой подборки укажи автора или название издания в `source` и страницу оригинала в необязательном поле `url`. Сохраняй доступное изображение, которое разрешено использовать в этой коллекции.

Ниже карточка второго слайда из [разбора затмения](../assets/eclipse-study/README.md). Путь верен, если временный JSON лежит рядом с изображением.

```json
[{
  "image": "result-2.png",
  "source": "Солнечное затмение",
  "slide": 2,
  "task": "Сравнить три похожих явления по видимому признаку",
  "principle": "Три диска показаны рядом на общем фоне. Подписи у края диска помогают различить белую корону и яркий солнечный обод.",
  "layout": "Три колонки с изображениями на одной высоте и пояснением под каждым",
  "use_when": "Нужно научить узнавать несколько похожих объектов по внешнему признаку",
  "avoid_when": "Нужно показать последовательные фазы одного процесса"
}]
```

Из папки `presentation-craft` выполни:

```sh
python3 scripts/collect_slide_patterns.py "/путь/к/отбору.json"
python3 scripts/search_slide_patterns.py --personal "сравнить похожие объекты"
```

Команда проверяет изображения через Pillow, сохраняет собственные копии и строит поисковый индекс. Библиотека по умолчанию находится в папке «Документы/Библиотека слайдов» пользователя (`~/Documents/Библиотека слайдов`). Для другого постоянного места задай `PRESENTATION_PERSONAL_LIBRARY` с путём к папке. Для отдельной коллекции передай `--library "/путь/к/папке"` при записи, а при поиске — `--file "/путь/к/папке/catalog.jsonl"`. Папку можно переносить целиком.

Точные копии изображений пропускаются, даже если изменилось имя файла. Похожие слайды с разным кадром или композицией сравнивает исполнитель при отборе. В ответе назови добавленные слайды и приёмы. Успех записи означает, что карточка доступна для поиска и [просмотра в галерее](slide-pattern-search.md).
