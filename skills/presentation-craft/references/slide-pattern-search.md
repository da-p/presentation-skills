# Поиск и рабочая подборка референсов

Подборки делай для разных задач объяснения и художественных направлений. Повторно используй подходящую подборку для похожих слайдов, сохраняя их индивидуальные решения. Полный поиск на каждом слайде не обязателен.

Библиотека — внешняя необязательная зависимость. Путь передаётся через `--file`, переменную `PRESENTATION_PATTERN_LIBRARY` либо локальную настройку `references/library.local.json` с полем `source`. Изображения задаются через `--image-root`. В переносимый пакет личная библиотека не входит. Если её нет, используй доступные референсы пользователя, внешние источники или собственный поиск; не объявляй невиденные изображения изученными.


Полные описания хранятся в вашем файле JSONL. По умолчанию индекс получает то же имя с расширением `.sqlite`. Он содержит поисковые карточки, семейства и адреса записей. Поиск не читает JSONL; выбор по ID читает только нужные записи. `recipe`, `quality` и `confidence` сохраняются без сокращения в оригинале. Размер индекса на диске не равен объёму контекста модели: выдача ограничена числом кандидатов.

Если есть [личная коллекция удачных слайдов](collect-slides.md), поищи в ней по задаче читателя. Команда `search_slide_patterns.py --personal "запрос"` выбирает её явно. При подключённой внешней библиотеке ищи в ней отдельным вызовом, при необходимости сохраняя свою подборку для каждого каталога. Для галереи с `--personal` папка изображений определяется автоматически.

## Двухэтапный отбор

**1. Найди около 30 кандидатов.** Начинай с задачи читателя, устройства данных и ограничений. Из папки навыка:

```sh
python3 scripts/search_slide_patterns.py "сравнить два тарифа по одинаковым условиям" --compact --pool "/путь/Подборка референсов.json" --slide s02
```

Команда создаёт подборку для новой задачи или обновляет запрос существующей. `--compact` оставляет принцип, композицию, применимость и ограничения без повторяющегося описания изображения; полные записи доступны по ID. Без `--pool --slide` выводятся только карточки. По умолчанию и максимум — 30 кандидатов; `--limit` позволяет сократить выдачу. Если совпадений меньше, программа не дополняет список случайными примерами.

Задача и способ представления имеют больший вес, чем стилистические совпадения. Русские формы слов и близкие понятия нормализуются при построении индекса. Балл поиска отражает текстовое совпадение, а не качество дизайна. Это первичный поиск, не содержательное решение.

**2. Выбери до шести по описаниям.** Сначала оцени, решает ли пример задачу: прочитай принцип, композицию, тип данных, применимость, ограничения и неопределённости. Количество объектов, объём текста и роль фотографии при необходимости уточни в полном рецепте через `--ids`. Затем среди подходящих выбери разные способы объяснения и создания образа. Цветовые варианты одного макета и почти одинаковые кадры не добавляют самостоятельного решения. Несколько примеров из одной презентации допустимы, если предлагают существенно разные приёмы.

Для каждого выбранного ID сформулируй **почему подходит этому материалу** и **чем дополняет остальные**. Разнообразие не оправдывает неподходящий пример. Если полезных вариантов меньше шести, оставь меньше; если нет ни одного — расширь запрос или проектируй самостоятельно. Оценку делает исполнитель по содержанию, программа проверяет состав и сохраняет обоснование; автоматический балл не заменяет этот шаг.

Запиши временный файл отбора, например `/путь/.tmp/отбор-s02.json`. Ниже показана структура; ID должны входить в фактическую выдачу, пояснения должны соответствовать текущему заданию:

```json
{
  "basis": "descriptions",
  "note": "Выбраны общая матрица и параллельные колонки; повторяющиеся варианты карточек исключены.",
  "selected": [
    {"id":"ref-01","fit":"Одинаковые условия двух тарифов можно сопоставить по общим строкам.","difference":"Единая матрица вместо отдельных карточек."},
    {"id":"ref-02","fit":"Колонки позволяют сравнить цену и состав каждого тарифа.","difference":"Каждый тариф читается целиком; общие строки сохраняют сопоставимость."}
  ]
}
```

```sh
python3 scripts/search_slide_patterns.py --pool "/путь/Подборка референсов.json" --slide s02 --select "/путь/.tmp/отбор-s02.json"
python3 scripts/search_slide_patterns.py --pool "/путь/Подборка референсов.json" --slide s02 --show-selection
```

Выбор, причины, основание и номер редакции сохраняются в существующей подборке. Отдельный постоянный журнал не нужен; временный файл служит только входом команды. При повторном `--select` прежний выбор заменяется. В `note` кратко сохраняй существенную причину пересмотра. Пустой `selected` допустим с пояснением. Повторы ID, чужие ID, более шести примеров и пустые обоснования отклоняются без изменения подборки.

## Визуальная выдача

Галерея создаётся **только из сохранённого отбора**, в указанном исполнителем порядке:

```sh
python3 scripts/search_slide_patterns.py --pool "/путь/Подборка референсов.json" --slide s02 --gallery "/путь/.tmp/референсы-s02.html" --image-root "/путь/Библиотека слайдов"
```

`--image-root` — действительная папка библиотеки, относительно которой разрешается `source.file`, например корень, содержащий `Все слайды/`. Личный путь автора не зашит в программу. Изображения не входят в навык; не копируй библиотеку целиком ради просмотра.

Автономный HTML показывает изображения, ID, принцип, причины выбора и отличия. Применимость, ограничения и неопределённости раскрываются в карточке. Открой файл доступным браузером или средством просмотра HTML; сравни композицию, пропорции, плотность, типографику и роль изображения. Мелкие детали рассмотри в оригинале. Если просмотр HTML недоступен, открой выбранные изображения отдельно.

**После просмотра пересмотри выбор.** Убери визуальные повторы и примеры, чья применимость не подтвердилась. Замену возьми из оставшихся кандидатов либо расширь поиск. Посмотри также изображения новых кандидатов. Повтори `--select` с `basis: "images"` и конкретным результатом проверки в `note`, даже если состав остался прежним; затем при необходимости создай обновлённую галерею. Если замены пока изучены только по описаниям, сохраняй `basis: "descriptions"` до просмотра. Поле `basis` — запись выполненной проверки исполнителем, а не автоматическое распознавание изображения.

Галерея читает только выбранные записи и не меняет подборку, индекс или план. Миниатюры не отмечают полные рецепты прочитанными: используй `--ids` для подробного разбора `recipe`, `quality`, `confidence`, если их ещё нет в текущем контексте.

Поддерживаются локальные PNG, JPEG, GIF и WebP до 10 МБ. Файл сверяется с отпечатком в базе. Недоступное, изменённое или неподдержанное изображение получает явную отметку; оно не считается просмотренным. Программа ничего не скачивает, не запускает сервер и не загружает внешние ресурсы. Ссылка на источник доступна для отдельного открытия.

Существующий HTML не перезаписывается: выбери свободный путь в том же временном каталоге. `--limit` ограничивает поиск, а не сохранённый отбор. Команды поиска, сохранения выбора и создания галереи выполняются отдельно. Прямая галерея из запроса или `--ids` больше не поддерживается: сначала содержательный отбор через `--select`.

## От найденного рецепта к слайду

Различай найденную карточку, прочитанный рецепт, просмотренное изображение и применённый приём. Для выбранного кандидата прочитай `recipe`, `quality`, `confidence` и рассмотри изображение в галерее либо по `source.file` в установленном месте библиотеки либо по доступному `source.image_url` / `source.url`. Относительный путь разрешай по действительному расположению базы изображений, не считай его автоматически путём внутри навыка. Если изображение недоступно, отметь это: текстовый принцип можно испытать, но визуальный характер этого примера не проверен. Ищи другой доступный визуальный образец, если задача — выбор характера.

В существующем плане или `decision` с областью конкретного слайда кратко свяжи **ID → что переносишь → как меняешь под материал → что должно стать лучше**. Например: «Из рецепта берём общую шкалу; три ряда вместо двух; все значения подписаны, чтобы сравнение не требовало возврата к таблице». Название «карточки» или «крупные цифры» без отношения к содержанию недостаточно. Не копируй рецепт целиком в план и не создавай отдельный журнал. Если кандидат отклонён, сохраняй существенную причину; если подходящего нет, зафиксируй собственное решение вместо формальной ссылки.

На прототипе проверь, что выбранный принцип действительно виден и сохраняет существенные связи. При поиске характера дополнительно сравни типографику, пропорции, плотность и роль изображения с просмотренным примером. Референс не обязывает повторять его макет, но факт чтения рецепта не доказывает переноса приёма. Выбранные ID и причины доступны при восстановлении контекста; для продолжения не нужно заново читать всю базу.

## Семейства

Для знакомства с вариантами подачи прочитай нужное описание в [справочнике семейств](slide-pattern-families.md). Для поиска в подключённой библиотеке используй команды ниже.

```sh
python3 scripts/search_slide_patterns.py --families
python3 scripts/search_slide_patterns.py "подчинение команд" --family hierarchy
```

Семейства — автоматически определённые гипотезы по текстам исходных описаний, не новая визуальная разметка. Один пример может иметь несколько меток. В каталоге приведены разные примеры, а не рейтинг лучших. Для непривычного материала проверь несколько семейств; фильтр может исключить удачный пример с неполной разметкой. При пустой или слабой выдаче расширь поиск без фильтра. Используй каталог для разнообразия приёмов, сохраняя общую систему оформления презентации.

Без запуска программ: найди нужное семейство в файле `slide-pattern-families.md` рядом с индексом библиотеки, выбери ID и прочитай указанные строки JSONL средствами выборочного чтения. При необходимости ищи по русским словам в JSONL с ограничением количества результатов. Весь файл в контекст не загружай.

## Подборка для презентации

В рабочей папке текущей презентации сохрани её план, например `План слайдов.json`. Это рабочий материал конкретной презентации, а не часть навыка:

```json
{"slides":[
  {"id":"s01","query":"обложка архитектура крупный объект короткий заголовок","constraints":{"text":"короткий","photo":true}},
  {"id":"s02","query":"сравнение двух тарифов по одинаковым условиям","constraints":{"objects":2,"no_preferred_option":true}},
  {"id":"s03","query":"иерархия руководитель три команды дополнительные связи"}
]}
```

В `query` включай мысль, структуру данных и существенные требования. `constraints` сохраняет условия для дальнейшей проверки агентом; программа не превращает их в автоматическое доказательство применимости. Можно добавить `family`, если семейство уже осмысленно выбрано.

```sh
python3 scripts/search_slide_patterns.py --plan "/путь/План слайдов.json" --pool "/путь/Подборка референсов.json"
python3 scripts/search_slide_patterns.py --pool "/путь/Подборка референсов.json" --slide s02
python3 scripts/search_slide_patterns.py --pool "/путь/Подборка референсов.json" --ids ref-01 ref-02 ref-03
```

План обрабатывается за один запуск. Подборка хранит до 30 первоначальных кандидатов **для каждого слайда отдельно**, короткие карточки, содержательный отбор и прочитанные полные записи. Общий объём не ограничивает охват слайдов; `exceeds_target` — информационный признак, не причина сокращать кандидатов. Не загружай всю подборку в контекст: получай карточки конкретного слайда, сохранённый выбор через `--show-selection` или полные записи по ID.

Повторный запуск с тем же планом использует готовые результаты и сохраняет выбор. Старые подборки из шести кандидатов расширяются до 30 при следующем поиске или обработке плана. Изменение задания или ограничений слайда сбрасывает его отбор; изменение базы — прежние результаты при пересборке. Обнови выбор перед созданием галереи. Для добавления слайда обнови план и повтори `--plan` либо передай запрос с новым `--slide`.

Если текущие кандидаты не подходят, запроси другие:

```sh
python3 scripts/search_slide_patterns.py "повторение одинаковых символов для количества" --pool "/путь/Подборка референсов.json" --slide s03 --expand
```

Новый запрос или `--expand` обращается к общему индексу и сбрасывает прежний отбор. При менее чем трёх совпадениях внутри подборки поиск расширяется автоматически; если кандидаты изменились, потребуется повторный выбор. Применимость найденного оценивает исполнитель по двухэтапному порядку выше.

Выбор по `--ids` сохраняет полные рецепты в подборке. Повторное чтение берёт их из этого сохранения. Если записи уже есть **в текущем контексте**, добавь `--unread`: повторно показанные записи не будут выведены. После смены контекста используй обычный `--ids`, чтобы восстановить содержание. Флаг `cached` в короткой выдаче означает наличие записи в файле подборки, а не в памяти модели.

## Контекст в существующем плане

Поиск хранит кандидатов и выбор в подборке. Содержание, решения и результаты этапов остаются в [едином рабочем плане](handoff.md). Укажи в нём ID выбранных примеров и что переносится; не регистрируй каждое изображение отдельным протоколом.

Для продолжения старого проекта доступен `presentation_context.py restore PLAN [--slide ID]`: он читает прежние решения, замечания и версии файлов, сохраняя исходные поля. Команды `file`, `decision` и `issue` нужны только если проект уже использует этот механизм. Их справка доступна через `--help`. Новый маршрут использует компактное состояние `presentation_pipeline.py` и не требует дублирующей регистрации.

Решение автора не является согласием пользователя. Старые замечания сохраняются; устаревшая проверка требует просмотра затронутого материала. Нельзя менять отпечатки только для снятия предупреждения. Для общего комплекта ранний результат по одному слайду не означает принятия всех остальных.

## Формат своего каталога

Сохраните файл JSONL в UTF-8. Первая строка описывает каталог. Каждая следующая строка содержит одну карточку со своим `id`. Ниже приведён пример для одного изображения.

```jsonl
{"record_type":"metadata","schema_version":"1.0.0","language":"ru"}
{"id":"ref-01","summary":"Два варианта сравниваются по общим строкам","message_role":"Сравнение","visuals":[],"layout":"Таблица","source":{"file":"images/table.png","sha256":"<SHA-256 файла table.png>","url":""},"tags":{"tasks":["сравнить варианты"],"slide_role":"Сравнение","data_type":["числа"],"layout":["таблица"],"style":[]},"recipe":{"solves":"Сравнить цену и срок","principle":"Каждая строка задаёт один критерий","essential_relationships":["общие строки"],"applicability":["у вариантов одинаковые показатели"],"avoid_when":["показатели несопоставимы"]},"confidence":{"observation":"high","interpretation":"high","uncertainties":[]}}
```

Для галереи подставьте путь к своему изображению и его контрольную сумму SHA-256. `--image-root` в этом примере указывает на папку, где лежит `images`. Адрес оригинала в `source.url` можно оставить пустым. В дополнительных полях карточки можно сохранить данные об источнике и качестве разбора. Поиск использует SQLite с поддержкой FTS5.

## Обновление и проверка

После изменения канонической базы перестрой индекс и каталог:

```sh
python3 scripts/build_slide_pattern_index.py
python3 scripts/search_slide_patterns.py --verify
```

Обычные запросы сверяют размер и время изменения базы. `--verify` дополнительно читает весь файл и проверяет SHA-256; чтение отдельной записи проверяет её собственный хеш. Устаревший индекс выдаёт ошибку вместо молчаливого использования старых описаний. Индекс можно восстановить из JSONL; самостоятельных правок в нём не делай. Для иной базы предусмотрены `--file` и `--index`.
